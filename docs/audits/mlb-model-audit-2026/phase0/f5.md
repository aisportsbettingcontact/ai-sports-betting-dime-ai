# F5 (First Five Innings) — ML / RL / Total — Phase 0 Dossier

Audit session date: 2026-07-25. Evidence classes: **VERIFIED** (code read this session, cited
file:line), **INFERRED** (reasoned from verified facts, reasoning stated), **UNKNOWN**.

## Overview

The F5 markets (moneyline, run line ±0.5, total) are priced by the same Python Monte Carlo engine
that prices the full game: `server/MLBAIModel.py` (`project_game` → `MonteCarloEngine.simulate` →
`MarketDerivation.derive`), spawned per-slate by `server/mlbModelRunner.ts` (VERIFIED
mlbModelRunner.ts:1236-1356). **F5 scores are NOT a separate innings-1–5 simulation and NOT a
truncation of the full-game sample** — they are an *independent second sampling pass* from the same
NB-Gamma mixture, with each team's full-game mean scaled by a fixed share constant
`F5_RUN_SHARE = 0.5618` and a ±10 % team-tendency adjustment (VERIFIED MLBAIModel.py:1222-1271).
F5 ML is priced three-way (home / away / push) with the simulated tie rate Bayesian-blended
60/40 toward an empirical 15.07 % push prior (VERIFIED MLBAIModel.py:1284-1302). The F5 run line
is hard-coded at ±0.5 and priced by normalizing P(home wins F5) vs P(away wins F5), i.e. ties are
*excluded* from RL pricing (VERIFIED MLBAIModel.py:1305-1310, 1937-1942) [FIXED in Phase 4 —
M-205: `p_f5_away_rl` is now `margin < +0.5` so the away +0.5 side covers ties; the two sides
partition all outcomes and sum to 1.0]. The F5 total is priced at
a **synthetic line — full-game book total × 0.555, snapped to nearest 0.5 — never at the book's
actual F5 total** (VERIFIED MLBAIModel.py:1926-1936). Book F5 lines (FanDuel NJ via Action Network)
are scraped by a separate pipeline (`server/mlbF5NrfiScraper.ts` + `server/ActionNetworkF5NrfiAPI.py`)
that runs only after 7 AM EST, and are never fed back into the model. Results land in the `games`
table's `modelF5*` columns, are served to any logged-out client via the public `games.list` tRPC
procedure, but as of this audit **no live end-user page renders them** — the two F5 UI components
are dead code and only the owner-only `/admin/model-results` page consumes F5 data.

INFERRED (from the above): F5 is **not starter-only**. Because F5 mu = full-game mu × 0.5618 and
the full-game mu already blends starter innings and bullpen-quality innings (MLBAIModel.py:725-729),
the bullpen's contribution to innings 6–9 is proportionally baked into the F5 projection. A team
with an elite starter and a bad bullpen gets its F5 mean *inflated* by the bullpen share; the only
F5-specific correction is the team-level F5-RS tendency clamped at ±10 %.

## Model mechanics

### Simulation and pricing flow (all VERIFIED)

1. Full-game sampling: `home_9/away_9 ~ NBGammaMixture(mu, var)` with 400 000 sims
   (MLBAIModel.py:919-925; SIMULATIONS=400_000 at line 68), extra innings resolved with ghost
   runner for the FG markets only (lines 936-958) — extra innings never touch F5.
2. F5 mu: `mu_f5 = mu_fullgame * 0.5618`, then team F5-RS adjustment
   `adj = clip((team_f5_rs − 2.484)/2.484 × 0.10, −0.10, +0.10)`; `mu_f5 *= (1+adj)`
   (MLBAIModel.py:1222-1267).
3. F5 variance: `var_f5 = max(var_fullgame × 0.5618, mu_f5 + 0.05)` (MLBAIModel.py:1268-1269).
4. Independent re-sampling: `home_f5/away_f5 ~ NBGammaMixture(mu_f5, var_f5)` — integer-valued
   negative-binomial draws (sample() returns `rng.negative_binomial` values,
   MLBAIModel.py:806-812), so ties and half-run cover events are exact (lines 1270-1273).
5. F5 ML three-way: raw `P(home)`, `P(away)`, `P(tie)` from the sample;
   `p_push_adj = 0.6·p_push_raw + 0.4·0.1507`; home/away rescaled so the three sum to 1
   (MLBAIModel.py:1284-1304). Consistency assert: three-way sum within ±0.001 (lines 1319-1322).
6. F5 ML pricing: two-way conditional no-vig on (home|no-push, away|no-push), then multiplied back
   by `(1 − p_push)` to absolute scale; `prob_to_ml` of those absolute probabilities produces
   `f5_ml_home/f5_ml_away` (MLBAIModel.py:1896-1917). **Note**: because odds are taken on
   *absolute* (push-inclusive) probabilities, the two fair MLs overround to less than 100 %
   (sum of implied ≈ 1 − p_push ≈ 0.85) — they price a tie as a *loss*, whereas book F5 ML pushes
   on tie (INFERRED from settlement convention). [CORRECTED — the originally quoted code comment
   "push=refund three-way pricing" does not exist; "refund" appears nowhere in MLBAIModel.py. The
   actual comments (1277-1283 and "this is how DK prices F5 ML" at 1900) describe the conditional
   no-vig construction but never state a tie-settlement convention, so the conflict is with the
   book convention, not with any in-code claim.]
7. F5 RL: fixed `F5_RL = −0.5`; `p_f5_home_rl = P(margin > 0.5)` (= P(home wins F5)),
   `p_f5_away_rl = P(margin < −0.5)` (= P(away wins F5)); those two are then
   `remove_vig`-normalized against each other and converted to odds
   (MLBAIModel.py:1305-1310, 1937-1942). **Ties are excluded from both sides** — but on a ±0.5
   line a tie is a *win for the +0.5 side*, not a push (the backtest itself acknowledges "push
   impossible with integer scores and 0.5 line", mlbMultiMarketBacktest.ts:537). The stored RL
   cover probabilities are therefore conditional-on-no-tie, not true cover probabilities.
   [FIXED in Phase 4 — M-205: away condition changed from `margin < −0.5` to `margin < +0.5`
   (ties cover the +0.5 side), a partition-sum assert was added, and `remove_vig` is now a pure
   normalization; newly stored RL cover probabilities are true cover probabilities.]
8. F5 total: `f5_ou_line = bookFG_total × 0.555` (or `exp_f5_total` if no book total), snapped to
   nearest 0.5 via `_nearest_half` (round(x·2)/2, MLBAIModel.py:519-521 [CORRECTED from 521-523]); over/under computed at
   that snapped line with integer-line push mass split 50/50; no-vig; odds
   (MLBAIModel.py:1925-1936).
9. Diagnostics: separate inning-by-inning simulation (I1–I9 weights) is only used for a
   consistency check against the direct F5 sample (|Δ| < 0.50 runs) and for the inning JSON
   columns — it does not feed F5 pricing (MLBAIModel.py:1338-1350, 1398-1411).

**F-2 detail (VERIFIED this session):** `modelF5AwayRunLine`/`modelF5HomeRunLine` appear in no
schema (drizzle/schema.ts:398-468 has only book `f5AwayRunLine`/`f5HomeRunLine`; census
schema-columns.tsv has no such columns). Drizzle v0.45.2's `buildUpdateSet` iterates
`Object.keys(tableColumns)` and silently drops set-object keys that aren't table columns
(VERIFIED node_modules/drizzle-orm/mysql-core/dialect.cjs:111-129), and the `.set()` type accepted
the extra keys (probe compile passed, this session). So the model's RL side labels are silently
discarded: **nothing in the DB records which side the model's F5 RL odds refer to.** Note the
dropped literals (`away='-0.5'`, `home='+0.5'`) also contradict the backtest's fixed convention
(home −0.5 / away +0.5, mlbMultiMarketBacktest.ts:534-537, 557, 576).

Invalidation path: when the FG RL sign-flip guard fires, all FG model fields are nulled atomically
— **the modelF5\* fields are NOT in the null list**, so stale F5 numbers survive an FG
invalidation until the re-run completes (VERIFIED mlbModelRunner.ts:2368-2398; INFERRED
consequence — the immediate targeted re-run at 2600-2622 normally closes this window quickly).
