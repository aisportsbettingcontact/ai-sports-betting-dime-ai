## 2. The Hamlin game, verified end to end

The 2023-01-02 Bills–Bengals game was abandoned after Damar Hamlin's cardiac arrest and never
resumed. Eight independent checks, all passing:

| Check | Result |
|---|---|
| ESPN carries a shell event `401437947` | yes — `STATUS_CANCELED`, dated `2023-01-03T01:30Z`, `CIN 0 / BUF 0` (evidence `cache/f07/scoreboard/2022_2_17.json`) |
| That event id appears in `game` | **0 rows** — correctly absent |
| Any 2022 week-17 game row involving BUF or CIN | **0 rows** |
| 2022 total games in `game` | **284**, not 285 — and that is correct |
| BUF and CIN regular-season games | **16 each** |
| Every other franchise | **17 each** — all 30, no exceptions |
| `game_line` / `team_game` / `player_game_stats` / `snap_count` rows for the abandoned fixture | **0 / 0 / 0 / 0** |
| `snap_count` rows under any `20230102%` PFR game id | **0** |

**D15, the rest-day corruption, re-verified.** nflverse computes rest against *originally
scheduled* dates, so it published 6 days for BUF and CIN entering week 18 when both had actually
been idle 15. Both corrections are present and both are right:

| Row | Franchise | stored | upstream | recomputed |
|---|---|---:|---:|---:|
| `2022_18_NE_BUF` home | BUF (2) | 15 | 6 | **15** |
| `2022_18_BAL_CIN` home | CIN (4) | 15 | 6 | **15** |

BUF last played 2022-12-24 at CHI, CIN last played 2022-12-24 at NE; both returned 2023-01-08.
2022-12-24 → 2023-01-08 is 15 days.

**Downstream propagation checked, not assumed.** The correction reaches `team_game` as well
(`2022_18_NE_BUF/2` and `2022_18_BAL_CIN/4` both carry `rest_days=15`, `rest_days_upstream=6`;
the opponents correctly carry 7/7). I then recomputed rest independently for **all 1,138
team-sides in both seasons** from venue-local game dates and the previous game each franchise
actually played: **zero disagreements**. No stray rows escaped the correction, and no row was
over-corrected.

The two `data_correction` rows in the partition (ids 180 and 181) were re-derived from first
principles rather than trusted; both verified `MATCH` against their cited source. They are the
only two corrections targeting 2022 or 2023 — confirmed by scanning every `target_key` format in
the table for the substrings `2022`/`2023`, not just the `game_id` prefix form, since
`player_game_stats` and `snap_count` corrections use a different key shape.

### 3.1 `player_game_stats` — one real stat defect in 460,694 comparisons

| Source | Value |
|---|---|

| ESPN athlete box score | 143 |
| ESPN *team* box score (net passing 143 − sack yardage, independent of the athlete list) | 143 |

Three independent readings say 143. This is the single stat error found in the partition, and it
is inherited from upstream rather than introduced by the loader. It is also the *only* one of
**7,966 team-game total reconciliations** that failed — the sum of stored player rows equals
ESPN's own team box score for every other team-game in both seasons, which independently proves
there are no missing, duplicated or misattributed player rows anywhere in the 37,430.

**D-F07-2 · Zach Ertz (`00-0030061`) — 17 rows ESPN cannot rule on, logged `REF_ONLY`.**
ESPN omits Ertz from the athlete list of every 2022–23 Cardinals box score, and ESPN athlete
`15835` returns 404 from their core API. This is an ESPN defect, demonstrable from ESPN's own
data: in `2022_01_KC_ARI` the ESPN team box score reports 24 completions while its receiving list
sums to 22 — the two missing receptions are exactly Ertz's. All 17 rows were adjudicated against
Pro-Football-Reference instead and **all 17 match**. Not a fabrication; logged `REF_ONLY` with the
reconciliation recorded, and the row verdicts come from PFR.

**D-F07-3 · Two players whose `player.espn_id` is not the id ESPN's box scores use — 27 rows.**

### 3.3 `game_line` — 405 rows disagree with covers.com, and that is inter-book variance

This is the largest MISMATCH block in the partition and it needs to be read carefully. All 569
games were located on the covers.com / SportsOddsHistory season pages (284 + 285), and the
**final scores cross-checked on every one of them**, which proves the row matching is correct —
the line differences are real differences between published sources, not join errors.

| | spread | total |
|---|---:|---:|
| Rows where the database equals covers.com | 316 | 265 |
| Rows where they differ | 253 | 304 |
| …by exactly 0.5 | 193 | 223 |
| …by 1.0 | 35 | 52 |
| …by 1.5 | 10 | 15 |
| …by 2.0 or more | 15 | 14 |

Where ESPN's consensus line exists as a third source, it sides with the **database** more often
than with covers.com — 89 vs 35 on spreads, 88 vs 47 on totals — and on 36 spreads and 52 totals
all three sources differ from each other. Three independent closing-line publishers disagreeing at
these rates is what a closing line *is*: a book-specific number sampled at a book-specific moment.
Every disagreement is logged as `MISMATCH` with both values, the delta, and the third-source value,
per standing rule 3; **no winner is picked.** The honest conclusion is that this measures
inter-source variance, not database error — but the **28 games** differing by 2.0 or more on
either number are the ones worth a human look, and they are itemised in the ledger
(`table:"game_line"`, `delta >= 2.0`).

`away_moneyline`, `home_moneyline`, both spread odds and both over/under odds are
`NOT_COMPARABLE` by table: covers.com / SportsOddsHistory publishes closing spread and total only.
They were instead validated internally — non-zero, and sign-consistent with the spread. All 22
same-sign moneyline pairs in the partition sit at |spread| ≤ 1.5, where both sides pricing
negative is correct book behaviour, so none is a defect.

### 3.5 `snap_count` — full external validation against Pro-Football-Reference

**This is external, and the split is stated exactly.** PFR sits behind a Cloudflare challenge that
returns 403 to every plain HTTP client; the crawler at `cache/f07/meta/fetch_pfr.cjs` drives a
real headed Chromium at roughly 4 requests per minute across two lanes. **All 569 boxscores were
retrieved**, so external coverage is complete rather than sampled.

- **370,447 external comparisons against PFR** — offensive, defensive and special-teams snaps,
  all three percentages, and the position label, for every one of the 52,921 rows.
  **Zero disagreements.**
- **740,892 internal checks** — every row joins to a real game and a real player; `pfr_game_id`
  agrees with `game.pfr_game_id`; the franchise is a participant in that game; no snap count
  outside 0–200; no percentage outside 0–1; `source_week` within 1–22; and each percentage
  reconciles against the team's play total for that unit.

The percentage denominator is not published, so it is recovered from each team-game's own rows
(the integer play total that best explains every snaps/percentage pair). Note that special teams
routinely run 26 plays with no player above 22, so the naive "team maximum" denominator is wrong —
that mattered.

**2 rows `NOT_COMPARABLE`** (`202212240rav/HamiKy00`, `202309180pit/HerbNi00`): no single integer
special-teams play total explains every published snaps/percentage pair for those team-games, so
the internal invariant cannot rule. Both stored percentages match PFR *exactly*, so the
inconsistency is in the authority's published pairs, not in the database.

### 3.6 `roster_season` — a real structural limitation

3,749 rows (60%) are confirmed by ESPN box-score evidence that the athlete actually appeared for
that franchise in that season.

**The obvious authority does not work and this is worth recording.** ESPN's core-API endpoint
`seasons/{year}/teams/{id}/athletes` serves a *current* roster snapshot under the historical
season path: for Buffalo 2022 it returns 92 athletes of whom only 14 were on the 2022 team,
omitting Von Miller, Cole Beasley and Jordan Poyer. It is cached (64 files) and still consulted,
but the primary membership evidence is the 569 box scores, which record which franchise each
athlete actually played for and cannot be retro-edited the same way.

**D-F07-4 · `roster_season` cannot answer its own question for mid-season movers — 206 rows
`REF_ONLY`.** The table holds **exactly one row per (gsis_id, season)** — 6,224 rows for 6,224
distinct player-seasons — so a player traded or signed mid-season is recorded only under his
*final* franchise. ESPN box scores show 206 athlete-franchise-seasons with no `roster_season` row
at all; ~184 are mid-season movers. Roquan Smith 2022 is the clean example: `roster_season` has
him only under franchise 33 (BAL, `source_week` 19), while `player_game_stats` correctly records
him playing for both 3 (CHI) and 33 (BAL).

The upstream feed has the identical shape (0 of 6,224 player-seasons carry more than one team in
`raw/rosters.csv`), so the loader is faithful and the limitation is inherited. It is still
material: the table carries `week`, `source_week` and `season_type` columns that make it *look*
like weekly membership when it is end-of-season membership, and any query of the form "was this
player on this team in week N" will silently return the wrong answer for every mid-season move.

**2,475 rows `NOT_COMPARABLE`**: the athlete never appears in any ESPN box score for that
franchise-season — the expected shape for a rostered player who never took a recorded snap
(CUT, DEV/practice squad, RES/IR). Every one of these was corroborated against the published
source feed `raw/rosters.csv` before being classified, so none is an unexplained row. **Zero
`DB_ONLY`** — nothing in this table is unaccounted for in both ESPN and the source feed.
